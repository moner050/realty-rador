# 지도 집계 쿼리 성능 개선 설계

## 목표

기본 지도 조회가 전체 매물 행을 애플리케이션으로 전송하지 않고도, 현재 검색 조건에 맞는 단지 수·좌표가 있는 단지의 가격/매물 수·미표기 단지 수를 정확히 반환하게 한다. 정상 필터의 지도 응답은 30회 측정 p95 1초 이하를 목표로 한다.

## 관측 근거

- `ListingMapService.build_viewport(ListingSearchFilter(), None, 7)`는 121,529ms가 걸렸다.
- 현재 경로는 활성 비단기 매물 753,776개의 42개 컬럼을 ORM 객체로 전송·생성한 뒤 파이썬에서 단지별 집계한다.
- 10,000행 ORM 스트리밍만 1,509ms였고, 15,255개 ID의 좌표 조회는 134.5ms에 147행을 반환했다.
- 따라서 병목은 좌표 조회나 군집 계산이 아니라 전체 매물 행 전송과 ORM 구체화다.

## 선택한 접근

지도 전용 서비스는 기존 `ListingSearchService.map_candidate_rows()`가 만든 필터 문을 재사용하되, 엔터티 행을 스트리밍하지 않는다.

1. 전체 일치 단지 수는 현재 지도 후보 필터 문에서 `COUNT(DISTINCT listing_current.complex_id)`로 계산한다. 지도 범위가 있으면 기존 후보 문이 이미 OK 좌표와 범위를 적용하므로, 이 수 역시 현재 보이는 범위의 단지 수다.
2. 표시 가능한 단지는 동일 필터 문을 `ComplexCurrent`와 조인하고, `geocode_status=OK` 및 유효 좌표 조건을 적용한 뒤 SQL `GROUP BY complex_id`로 집계한다. 이 결과는 단지 ID, 이름, 주소, 좌표, 매물 수, 최저/최고가만 가진다.
3. 지도 범위가 있으면 후보 문이 적용한 좌표 범위를 그대로 보존한다. `map_initial` 요청은 라우트가 범위를 비운 상태로 호출하므로 전체 검색 결과의 단지 수와 미표기 수를 보여 준다.
4. 미표기 수는 전체 일치 단지 수에서 좌표를 가진 전체 일치 단지 수를 뺀다. 현재 지도 범위에서는 기존 후보 문이 OK 좌표만 남기므로 이 값은 0이 될 수 있으며, 초기 전체 조회에서는 아직 지오코딩되지 않은 단지 수를 뜻한다.
5. 서비스는 집계된 표시 단지 결과만 `ListingMapMarker`로 바꾸고 기존 Decimal 군집 함수를 그대로 사용한다.

## 의도적으로 하지 않는 일

- 새 인덱스, 마이그레이션, 좌표 테이블, 캐시 또는 읽기 모델을 추가하지 않는다.
- 페이지 요청에서 Naver 지오코딩이나 DB 쓰기를 수행하지 않는다.
- 대출 적격성/구매가능성처럼 파이썬 정책 평가가 필요한 필터의 기존 후보·정책 의미를 바꾸지 않는다. 이 경로는 올바름을 우선하고, 일반 SQL 필터 경로만 이번 성능 목표의 대상이다.
- 카드 목록, 지도 SDK, 군집 UI, 초기 지도 중심/확대 수준을 바꾸지 않는다.

## 동등성 규칙

- `matching_complex_count`는 현재 지도 후보 필터(지도 범위가 있으면 그 범위 포함)에 일치하는 서로 다른 단지 수다.
- `mapped_complex_count`는 같은 검색 필터에 일치하면서 저장된 OK 좌표가 있는 단지 수다.
- `unmapped_complex_count = matching_complex_count - mapped_complex_count`다.
- 지도 범위는 기존 후보 필터와 마커/군집에 동일하게 적용된다.
- 최저가, 최고가, 매물 수와 단지명/주소는 기존 파이썬 집계 결과와 같아야 한다.

## 오류 및 성능 검증

- SQL 필터와 파이썬 정책 필터의 분기를 명시적으로 유지하고, 일반 필터 집계가 기존 스트림 기반 결과와 동등한지 단위·통합 테스트로 비교한다.
- 수정 전/후 정상 필터 SQL을 기록하고 `EXPLAIN FORMAT=JSON`으로 인덱스 사용을 확인한다. `EXPLAIN ANALYZE`는 새 쿼리가 제한 시간 안에 끝난 뒤에만 실행한다.
- 30회 대표 호출의 p95가 1초를 넘으면 인덱스를 추가하지 않고 결과·계획을 기록한 뒤, 별도 읽기 모델 또는 인덱스 설계를 다시 승인받는다.

## 성공 기준

- 정상 필터 지도 데이터가 전체 매물 ORM 행을 전송하지 않는다.
- 기존 지도 숫자·좌표 있는 단지의 가격 범위·군집 입력이 동일하다.
- 지도 및 카드 요청은 읽기 전용이다.
- 전체 Python/Node 회귀 테스트와 새 집계 동등성 테스트가 통과한다.
- 실제 DB에서 새 정상 필터 지도 조회 30회 p95가 1초 이하이거나, 기준 미달 증거가 보존되어 다음 최적화 결정을 막지 않는다.
