# 실구매 가능성 계산 디자인

## 목표

매매 매물마다 사용자가 실제로 준비해야 할 현금과 매월 감당해야 할 비용을 같은 기준으로 보여주고, 두 기준을 모두 만족하는 매물만 검색할 수 있게 한다. 이 기능은 은행 또는 세무사의 심사 결과를 대체하지 않는다.

## 범위

- 매매(`SALE`) 매물만 계산한다. 전세·월세는 기존 정책대출 표시를 유지하고 이번 기능의 대상에서 제외한다.
- 기존 정책대출 판정 엔진의 결과를 재사용한다. 새 대출 상품, DSR 판정, 세법·중개보수 법정요율 계산은 추가하지 않는다.
- 검색 카드와 단지 상세의 개별 매물에는 계산 요약을 표시한다.
- `실구매 가능 매물만` 필터는 보유 현금과 월 총주거비 한도가 모두 설정된 경우에만 사용할 수 있다.

## 사용자 입력과 보존

기존 `ApplicantProfile.net_assets`는 정책대출 자격 판정용 순자산으로 유지한다. 구매에 바로 투입할 수 있는 현금과 의미가 다르므로 다음 필드를 별도로 추가한다.

| 필드 | 기본값 | 용도 |
| --- | --- | --- |
| `available_cash` | 없음 | 매수에 투입 가능한 현금. 미입력 시 현금 충족 여부를 판정하지 않는다. |
| `existing_monthly_debt_payment` | `0` | 기존 대출의 월 상환액. 월 총주거비에 합산한다. |
| `max_monthly_housing_cost` | 없음 | 사용자가 감당 가능한 월 총주거비 상한. 미입력 시 월 한도 충족 여부를 판정하지 않는다. |
| `closing_cost_reserve_bps` | `200` | 취득세·중개보수 등 계약 부대비용을 위한 계획 예비비율(기본 2.00%). 법정 비용 산정값이 아니다. |

모든 값은 현재의 인라인 개인 조건 모달과 게스트 쿠키/로그인 프로필 저장 흐름으로만 보존한다. 별도 설정 화면이나 새 DB 테이블은 만들지 않는다.

## 계산 계약

`PurchaseAffordabilityService`는 매물과 정책대출 평가 결과를 입력받아 불변 결과 DTO를 반환한다.

1. 가능한 정책대출 결과(`ELIGIBLE` 또는 `PROPERTY_ELIGIBLE`) 중 최대 한도를 선택한다. 한도가 같으면 금리가 낮은 상품을 선택한다.
2. 예상 부대비용 예비비는 `ceil(매매가 × closing_cost_reserve_bps / 10_000)`으로 계산한다.
3. 예상 필요 현금은 `max(0, 매매가 - 선택 대출 한도) + 부대비용 예비비`다.
4. 월 원리금은 선택된 대출 한도와 해당 금리로 30년(360개월) 원리금균등 상환 방식으로 계산한다. 금리 0%는 원금을 360으로 나눈다.
5. 월 총주거비는 `월 원리금 + 실제 월 관리비(없으면 0) + 기존 월 대출상환액`이다.

현금 또는 월 한도가 없는 경우에도 금액은 표시하되, `구매 가능` 또는 `불가`를 단정하지 않는다. 한도가 모두 있을 때만 현금과 월 총주거비를 각각 비교하여 최종 판정을 만든다. 가능한 정책대출이 없으면 대출액과 월 원리금은 0으로 계산하므로 현금 구매 가능성은 과장하지 않는다.

## 화면과 검색 흐름

매매 카드에는 다음을 한 블록으로 표시한다.

- `예상 필요 현금`, `선택 정책대출`, `부대비용 예비비`
- `월 원리금`, `관리비`, `기존 대출`, `월 총주거비`
- 입력 누락 시 설정 유도 문구, 입력 완료 시 현금·월 한도별 충족 여부
- “정책대출 기준 예상치이며 실제 대출·세금·중개보수는 계약 전 확인” 고지

검색 조건에는 `실구매 가능 매물만` 체크박스를 추가한다. 활성화하면 기존 정책대출 후보 SQL 범위 안에서 애플리케이션 계산을 적용해 두 한도를 모두 만족하는 매물만 반환한다. 이 방식은 목록 hot query에 조인이나 비인덱스 계산식을 넣지 않는다. 커서에는 새 필터와 사용자 프로필 fingerprint가 이미 포함되는 기존 계약을 사용한다.

그룹 검색은 단지 안에 조건을 만족하는 매매 매물이 하나라도 있을 때 해당 단지를 반환한다. 단지 카드에는 대표 매물 계산을 단정해 표시하지 않고, 개별 매물 목록에서 계산을 확인하게 한다.

필터가 활성화됐지만 보유 현금 또는 월 한도가 없으면 서버는 목록을 조용히 넓히지 않는다. 검색을 실행하지 않고 인라인 개인 조건 모달을 열도록 안내하는 오류 상태를 반환한다.

## 오류 경계와 비목표

- 이 계산은 현재 정책대출 엔진의 규칙과 금리만 사용한다. 은행별 DSR·신용·담보 심사, 한도 변경, 전입 의무는 보장하지 않는다.
- 2% 부대비용은 사용자가 조정 가능한 계획 예비비다. 취득세·중개보수의 법정 계산 결과로 표기하지 않는다.
- 매물 가격·관리비가 누락되면 해당 매물은 계산하지 않고 값 누락 사유를 표시한다.
- 실거래가·매물 생존 여부·공식 관리비 데이터는 다음 단계에서 별도 근거와 갱신 시점을 포함해 추가한다.

## 검증

- 순수 계산 단위 테스트: 최대 한도/낮은 금리 선택, 30년 원리금균등, 0% 금리, 부대비용 예비비, 입력 누락, 현금 구매.
- 프로필 직렬화·인라인 설정 테스트: 새 입력의 저장·복원과 이전 프로필의 안전한 기본값.
- 검색 통합 테스트: 일반·그룹 검색에서 정확한 조건 적용, 커서 재사용 거부, 입력 누락 시 명시적 오류, 기존 정책대출 필터와의 조합.
- UI 테스트: 카드 수치·고지·필터가 렌더되고, 서버 비밀값이나 계산 내부값이 노출되지 않는다.
- 전체 `python -m pytest -q`와 MySQL 환경에서 검색 벤치마크/`EXPLAIN ANALYZE`를 다시 확인한다.
