# 지도 중심 검색 워크스페이스 설계

## 목표

검색 조건을 바꾸고 지도에서 범위를 이동한 뒤 결과를 비교하는 흐름을 한 화면에 묶는다. 지도는 항상 중심에 두고, 현재 조건과 지도 영역 결과를 즉시 확인할 수 있게 한다.

## 범위와 원칙

- 기존 `ListingSearchFilter` 파라미터, 저장 필터, URL 직렬화, HTMX 검색과 지도 API 계약은 유지한다.
- 지도 이동으로 추가된 경계는 비영속이며, 카드 교체는 기존 지도 조회 규칙과 1.5초 대기 규칙을 유지한다.
- 검색 조건의 의미와 기본값은 바꾸지 않는다. 오직 입력 위치, 접힘 상태, 요약 표기와 조작 흐름을 바꾼다.
- 데스크톱과 모바일 모두 같은 단일 검색 폼을 사용한다. 같은 이름의 두 입력을 만들지 않는다.

## 화면 구조

### 1. 검색 작업 영역

페이지의 넓은 본문을 단일 지도 중심 열로 재구성한다.

1. 제목 줄에는 검색 초기화와 짧은 사용 안내만 둔다.
2. 지도 위의 고정 검색 막대에는 시도/시군구 선택, 단지명 키워드, 거래 유형, 가격 범위, `상세 필터` 버튼을 둔다.
3. 선택된 조건은 검색 막대 바로 아래의 읽기 쉬운 조건 칩으로 요약한다. 칩의 제거 동작은 현재 폼 값만 제거한 뒤 기존 자동 검색을 사용한다.
4. 지도 헤더에는 현재 결과 수, 정렬, 지도 상태와 `상세 필터` 버튼을 둔다. 지도 자체의 원형 집계/마커와 모달 동작은 변경하지 않는다.
5. 지도 아래에는 `현재 지도 영역 매물` 제목, 작은 갱신 상태, 기존 카드 목록과 페이지네이션을 둔다.

### 2. 상세 필터 패널

- 기존 상세 검색 조건은 우측에서 열리는 `dialog` 기반 패널로 이동한다.
- 패널은 현재의 대출/자격, 주거/거주, 교통, 옵션/안전 카테고리 구분을 유지하되, 한 번에 한 카테고리만 펼쳐 가독성을 확보한다.
- 각 카테고리 제목에는 해당 카테고리에서 설정된 조건 수를 표시한다.
- 패널 하단에는 `적용`과 `전체 초기화`를 고정한다. `적용`은 기존 폼을 한 번 제출하고 패널을 닫는다. `전체 초기화`는 기존 초기화 URL로 이동한다.
- 패널을 닫아도 아직 적용하지 않은 입력 값은 유지한다. 사용자가 적용하면 그 값이 URL·저장 필터·지도 API URL에 같은 방식으로 반영된다.

### 3. 반응형 동작

- 데스크톱에서는 검색 막대가 지도 폭에 맞춰 한 줄 또는 두 줄로 배치되고 상세 패널은 오른쪽에서 너비 약 28rem으로 열린다.
- 모바일에서는 검색 막대의 핵심 입력을 두 줄로 배치하며, 상세 필터 패널은 화면 전체 폭에 가깝게 열린다.
- 카드와 지도는 기존처럼 세로로 쌓인다. 모바일에서 별도의 지도/목록 보기 전환은 추가하지 않는다.

## 데이터 및 상호작용 흐름

1. 사용자가 핵심 조건을 바꾸면 기존 HTMX 자동 검색이 전체 검색 영역을 교체하고 URL·저장 필터를 갱신한다.
2. 새 검색 영역에서 지도 스크립트가 다시 마운트되고, 지도는 기존 수도권 시작 위치와 사용자 조작 뒤 1.5초 조회 규칙을 따른다.
3. 사용자가 지도를 이동하면 기존 `map-data`와 `map-cards` 요청만 발생한다. 검색 폼 저장이나 URL 변경은 발생하지 않는다.
4. 카드 또는 단지 클릭은 기존 지도 포커스 기능을 사용하고, 실제 단지 마커는 기존 단지 상세 모달을 연다.
5. 조건 칩 제거와 상세 필터 적용은 같은 폼 제출 경로를 사용하므로, 별도 필터 파서·DB 쿼리·마이그레이션은 추가하지 않는다.

## 접근성 및 오류 처리

- 상세 필터는 제목, 닫기 버튼, 명시적 적용 버튼, 키보드 포커스가 있는 `dialog`로 구현한다.
- 토글 버튼에는 현재 열림 상태를 나타내는 `aria-expanded`를 설정한다.
- 검색·지도 카드의 작은 진행 상태를 유지하며 전체 지도 위를 가리는 로딩막은 사용하지 않는다.
- 지도 스크립트가 없거나 요청이 실패할 때 기존 상태 문구와 현재 카드 목록을 그대로 유지한다.

## 검증

- 통합 템플릿 테스트: 단일 검색 폼 안에 지도, 핵심 조건 막대, 상세 필터 패널, 조건 요약, 지도 영역 결과가 존재하고 지도 데이터 속성이 보존됨을 확인한다.
- 브라우저 컨트롤러 테스트: 상세 필터 열기/닫기, 적용 시 단 한 번의 폼 제출, 칩 제거 시 해당 값 제거, 지도 이동 시 카드 요청의 비영속성을 확인한다.
- 기존 지도 계층 집계, 카드 교체, 목록-지도 포커스, 단지 모달 회귀 테스트를 유지한다.
- 브라우저 점검: 라이트/다크 모드, 데스크톱, 모바일 폭에서 텍스트 대비와 필터 패널의 스크롤·하단 적용 버튼을 확인한다.

## 제외 범위

- 검색 필터의 종류, SQL 조건, 저장 스키마, 지도 API 응답, 새 외부 API 호출은 변경하지 않는다.
- 새 지도/목록 보기 전환이나 좌측 고정 필터 열은 추가하지 않는다.
