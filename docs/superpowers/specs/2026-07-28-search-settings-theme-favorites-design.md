# 검색 화면 조건 설정, 라이트 모드, 즐겨찾기 설계

## 목표

독립 설정 화면을 제거하고 개인 자격 및 정책대출 조건 관리를 매물 검색 화면의 모달로 단일화한다. 라이트 모드에서 가격·면적 상세 조건, 고급 상세 조건, 개인 자격 모달의 텍스트와 입력값이 읽히도록 한다. 매물과 단지 즐겨찾기가 식별자와 표시 데이터를 올바르게 보관하고, 로그인 사용자는 DB에 보존한 목록을 다음 로그인에서도 복원한다.

## 범위

- 상단 네비게이션의 설정 탭을 제거한다.
- `GET /settings`는 검색 화면으로 리다이렉트한다. 독립 설정 템플릿과 화면 전용 `POST /settings` 처리기는 제거한다.
- 검색 화면의 `/settings/inline` 저장 경로와 조건 모달은 유지한다.
- 가격·면적 상세 조건, 고급 상세 조건, 조건 모달 내부의 하드코드된 다크 텍스트·배경을 공통 테마 토큰 또는 라이트/다크 쌍으로 교체한다.
- 즐겨찾기 카드에 ORM 객체를 직접 JSON 직렬화하지 않는다. 서버가 생성한 최소 직렬화 데이터만 카드 클릭 인자로 사용한다.
- 매물과 단지 모두 `article_id` 또는 `complex_id`를 포함한 데이터로 추가·제거한다.
- 비로그인 사용자는 기존 로컬스토리지 키(`rr_favorite_listings_v1`, `rr_favorite_complexes_v1`, `rr_favorite_group_mode_v1`)를 기준 저장소로 사용한다.
- 로그인 사용자는 기존 `/api/user/preference` API를 통해 `user_preference.favorites_json`에 저장하고, 페이지 시작 시 서버 목록과 로컬 목록을 중복 없이 병합한 뒤 화면과 로컬 저장소를 갱신한다.

## 설계

### 설정 화면 단일화

공통 헤더에서 `/settings` 링크를 삭제한다. 이전 북마크나 직접 주소에 대한 `GET /settings`는 `/`로 리다이렉트한다. 개인 조건 저장은 검색 화면의 비동기 `/settings/inline`만 사용한다. 이로써 사용자는 검색 화면의 왼쪽 조건 카드와 모달에서만 대출 조건을 확인·수정한다.

### 테마 대비

모달과 상세 조건의 레이블, 설명, 입력값, 카드 및 구분선은 `theme-*` 헬퍼 또는 명시적인 `text-slate-* dark:text-*`, `bg-* dark:bg-*` 쌍을 사용한다. 라이트 모드에서는 어두운 본문 텍스트와 밝은 표면을, 다크 모드에서는 기존의 밝은 본문 텍스트와 어두운 표면을 사용한다. 기능과 폼 필드 이름은 변경하지 않는다.

### 즐겨찾기 데이터 경계

검색 결과의 ORM 엔터티와 단지 그룹은 Jinja `tojson`으로 직접 전달하지 않는다. 라우트가 즐겨찾기에 필요한 원시 값만 가진 매물 및 단지 데이터 맵을 만든다. 카드 템플릿은 해당 맵의 JSON을 클릭 함수에 전달한다. 이는 현재 ORM/슬롯 객체가 `[]`로 직렬화되어 ID 검증에서 중단되는 문제를 해결한다.

매물 카드의 즐겨찾기 버튼은 명시적 `onclick` 경로를 사용하며 카드 상세 열기 이벤트를 중단한다. 단지 카드도 같은 식별자 계약을 사용한다. HTMX가 새 카드로 교체해도 각 카드 자체에 완전한 클릭 데이터가 있으므로 재초기화가 필요 없다.

### 로그인 보존

비로그인 상태에서 `FavoritesManager.save()`는 현재 즐겨찾기·단지·묶음 보기 값을 로컬스토리지에 저장하고 화면을 갱신한다. 로그아웃은 이 게스트 데이터를 삭제하지 않는다.

회원가입 또는 로그인에 성공해 검색 화면을 처음 로드할 때 `loadFromServerAndMerge()`는 게스트 로컬 목록과 해당 로그인 계정의 DB 목록을 `article_id`·`complex_id` 기준으로 중복 제거해 합친다. 합친 목록은 즉시 해당 계정의 `/api/user/preference`로 POST하여 `user_preference.favorites_json`에 보존하고, 같은 값을 로컬스토리지에도 유지한다. 네트워크 또는 서버 저장 실패 시 로컬스토리지 원본을 삭제하거나 덮어쓰지 않는다. 따라서 게스트가 회원가입하면 기존 즐겨찾기는 새 계정으로 이전되고, 로그아웃 후에도 브라우저의 게스트 목록은 남는다.

## 검증

- 템플릿 계약 테스트: 설정 링크와 독립 화면 렌더링이 제거되고 `/settings`가 리다이렉트됨을 검증한다.
- 템플릿 계약 테스트: 세 대상 UI에 라이트 모드 텍스트·표면 계약이 존재함을 검증한다.
- 즐겨찾기 계약 테스트: 매물·단지 버튼이 빈 배열이 아닌 ID 포함 JSON 데이터를 사용함을 검증한다.
- 사용자 환경설정 API 테스트: 로그인 사용자의 즐겨찾기 POST 후 GET 응답에 동일한 값이 보존됨을 검증한다.
- 브라우저 검증: 게스트에서 매물/단지 추가·제거 후 새로고침에도 목록이 남고, 회원가입 또는 로그인 성공 직후 해당 게스트 목록이 DB 계정 목록으로 병합·보존되며, 로그아웃·재로그인 후에도 복원됨을 확인한다.

## 비범위

- 검색 SQL, 대출 적격성 계산, 기존 필터 저장 동작 변경
- 설정 이외의 화면 구조 개편
