# 수동 크롤링 개수 제한 분석 계획 및 보고서

## 1. 분석 계획
- **목적**: 수동 크롤링(즉시 수집) 실행 시 매물이 1000개만 수집되는 현상의 기술적 원인을 분석하고 보고합니다.
- **수행 작업**:
  1. 수집기 어댑터(`SiteAAdapter`, `SiteBAdapter`) 소스 코드 분석
  2. 매물 생성 로직(`count` 제한 변수 등) 확인 및 동작 설명
  3. 결과 정리 및 마크다운 파일 저장

## 2. 분석 결과
- **SITE_A (1000개 수집)**:
  - 파일: `src/realty_radar/crawler/adapters/site_a/adapter.py`
  - 함수: `_generate_massive_seoul_gyeonggi_apartments()`
  - 원인: 모의 데이터 생성을 담당하는 해당 함수에서 `count = 1000`으로 고정되어 루프를 1000번 반복하며 매물을 생성하도록 하드코딩되어 있습니다. 이에 따라 SITE_A의 검색 파이프라인을 실행하면 매번 정확히 1000개의 매물이 생성되고 수집이 종료됩니다.
  
- **SITE_B (7개 수집)**:
  - 파일: `src/realty_radar/crawler/adapters/site_b/adapter.py`
  - 함수: `_generate_seoul_gyeonggi_listings()`
  - 원인: 이 함수에는 서울/경기의 특정 7개 아파트 매물 데이터 리스트가 고정 정의되어 있습니다. SITE_B 수동 수집 시에는 이 7개의 매물 데이터만 수집되도록 구현되어 있습니다.

## 3. 요약 및 대안
- 현재의 대량 수집은 테스트 및 시뮬레이션을 위해 각 어댑터 내부에 하드코딩된 모의 생성 데이터 개수에 의존하고 있습니다.
- 만약 수집 개수를 변경하고 싶다면, `SiteAAdapter` 내의 `count` 변수 값을 조절하거나, 설정 파일(`config.py` 또는 `.env`)로부터 수집 제한 개수를 읽어오도록 개선할 수 있습니다.
